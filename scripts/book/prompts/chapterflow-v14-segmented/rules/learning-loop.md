# Research-native learning loop

The chapter and its learning surfaces should serve this sequence:

1. Prime
2. Read
3. Apply
4. Test
5. Practice
6. Review

## Prime
- use 2 to 3 prediction or pretest questions per chapter blueprint
- prediction prompts should activate curiosity and prior knowledge
- do not turn priming into spoilers

## Read
- organize around 3 to 5 core concepts even when the public package surface is larger
- keep the internal concept budget small enough for working memory

## Apply
- scenarios should transfer the concept into modern contexts
- each scenario must teach a distinct application

## Test
- 10-question flagship quiz is allowed, but it should still map to distinct principles
- explanations should teach the mechanism, not only mark right and wrong

## Practice
- implementation plans must use specific triggers and observable actions
- avoid generic life coaching

## Review
- review cards should compress insight, not restate the recap
- retain metadata that can later feed spaced review in the product
