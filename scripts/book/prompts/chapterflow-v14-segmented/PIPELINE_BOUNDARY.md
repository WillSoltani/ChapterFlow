# Pipeline boundary

## Core autonomous content-generation pipeline
In scope:
- source discovery
- edition or translation lock
- frozen source bundle
- chapter sidecars
- chapter dossiers and outlines
- writer, editor, critic, converter, quiz, validator, patch / repair
- validated chapters
- release artifact
- final book JSON package
- core guards, lints, and validators

The core pipeline ends when those outputs exist and pass.

## Post-pipeline integration
Outside core scope, but can run autonomously afterward:
- register the book in the app
- create normalized package exports
- wire UI-facing metadata
- create or replace final cover
- map the cover asset
- run build and fix integration issues
- verify product-level rendering and routing

## Manual / recovery work
Not part of the normal happy-path pipeline:
- manual prose rescue
- manual syntax rescue
- extra editorial polish after formal guards already pass

## Cleanup
After successful release and integration only.
Retain final deliverables and the minimum audit trail.
