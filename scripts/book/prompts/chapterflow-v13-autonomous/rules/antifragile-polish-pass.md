Antifragile polish pass

Run this pass whenever `bookId: antifragile`.

Purpose:
- preserve Taleb's severe, payoff-aware register without flattening it
- clean metadata and package hygiene failures that make a strong chapter ship like a dirty artifact
- keep support layers and bridges as sharp as the body
- force the chapter's real limit to remain visible

Metadata repair:
- normalize title to `Antifragile: Things That Gain from Disorder`
- normalize author to `Nassim Nicholas Taleb`
- remove curly quotes, decorative punctuation, and odd hyphenation from metadata
- fill supported edition fields from the frozen source bundle
- require non-empty sourceText, sourceProvenance, and chapterRange
- ensure release and review-package book objects are internally consistent

Support-layer cleanup:
- convert partial or stale support shapes into the canonical package shape
- review cards must be tone objects with distinct gentle/direct/competitive variants
- implementation if/then plans must use `context` plus `plan`, not stale cue/response wrappers
- recap, review cards, and implementation surfaces must stay chapter-specific and payoff-aware
- remove generic coaching language from implementation surfaces
- rewrite any support surface that sounds softer, safer, or more generic than the body

Bridge cleanup:
- review the final support-layer handoff for the chapter
- make the bridge point to the actual next concept, not a generic continuation
- keep the bridge short, structural, and book-specific
- if the bridge explains the next chapter too broadly, tighten it to the conceptual hinge

Boundary cleanup:
- make the chapter's proper limit explicit where the chapter invites caricature
- examples:
  - not anti-arithmetic
  - not anti-theory
  - not anti-institution
  - not anti-risk
  - not anti-expert
  - not total passivity
- if the body already carries the limit, keep the support layer from contradicting it

Voice cleanup:
- prefer downside, exposure, survival, payoff, optionality, tail, convexity, and intervention language when the chapter genuinely needs it
- keep critiques narrow and specific
- remove motivational uplift, therapy phrasing, or vague resilience slogans
- keep competitive lines shorter and harsher, not noisier

Final read:
- if the package reads like a strong chapter inside a weak wrapper, keep polishing
- if the metadata looks dirty, fail it
- if the support layer sounds flatter than the chapter, rewrite it
- if the bridge feels decorative rather than structural, rewrite it
- if the chapter's limit disappeared, restore it before validation
