# v21 Failure-Mode Catalog

The single source of truth for what v21 must catch before any chapter ships. Each entry lists the v13 failure mode, the v21 enforcement mechanism, the severity tier, and the specific code location.

Severity tiers:
- **BLOCKER** — chapter cannot ship; final gate hard-fails.
- **MAJOR** — chapter ships only if voice-pass / writer can't fix after retries; logged.
- **MINOR** — advisory; logged but never blocks ship.

Anything not in this catalog is not a known v13 failure mode. If a new failure mode is identified later, add it here first, then add the enforcement.

## EXP. Behavior-change layer (experiencePlan)

The optional `experiencePlan` field (Layer A: `failureRecovery` + `transferPrompt`) is authored per-chapter — **never** dealt as a card with a copyable example (that is the card-seed convergence vector, PRs #144/#153). Every EXP check runs only when the field is present, so all fire **zero** on the current corpus. EXP1–EXP3 are chapter-level (finalGate); EXP10/EXP11 are cross-chapter (bookGate). Register hygiene (meta-reference B1, chapter-number B2, em-dash B5, banned phrases B4) is applied to every authored experiencePlan string via the shared `runRegisterChecks`.

| ID | Failure | Enforcement | Severity | Code |
|----|---------|-------------|----------|------|

A half-formed surface is worse than none. | `checkExperiencePlanStructure` validates non-emptiness + array bounds when the sub-object is present. | BLOCKER | [src/critics/experiencePlan.ts](src/critics/experiencePlan.ts) |

### `experiencePlan.behaviorLoop.readerPatterns` (RDRP) — the optional "which pattern fits you?" personalization layer

Same zero-fire-when-absent calibration as EXP*. ## MB. Model-bar (judgment-layer) quality axes

These are **not deterministic critics** and never fire at `gate-chapter`/`book-gate`. They are weighted axes of the publishable bar (`AXIS_RUBRIC`/`AXIS_WEIGHTS` in [src/critics/semantic/publishableBar.ts](src/critics/semantic/publishableBar.ts)), scored 0–1 by the QC reviewer/judge and reduced through `computeVerdict`. ### Why these critics matter as a class

The BP1–BP14 critics from earlier sessions and BP15–BP21 from this session all rely on **verbatim n-gram matching**. They detect "the same 5 / 6 / 8 words appearing in N chapters." A motivated writer agent can defeat all of them by inserting one unique token per chapter at the substitution point: every n-gram becomes unique, the bytewise audits pass, the reader receives garbage. AS1–AS4 detect the gaming patterns directly (not the absence of repetition). AS4 in particular uses word-multiset similarity (not n-gram identity) so token substitution does not evade it.

### What the writer agent should do when an AS finding fires

The right fix is NEVER to remove the salt token. The right fix is to rewrite the field as a different sentence in different words from a different angle. If the agent cannot produce a different sentence (after 3 honest attempts), the upstream issue is that the chapter source notes are too similar across chapters, or the chapter's central concept overlaps another chapter's — surface that to the operator. The gate-attempt tracker at `state/gate-attempts.json` warns when an agent re-runs the gate on the same chapter with the same blocker signature 3+ times.

### Coverage gap that remains

Cross-chapter prompt-template detection (AS4) currently runs on quiz prompts only. A motivated agent could attempt the same gaming pattern in example scenarios or breakdown paragraphs. Extending AS4 to other field types is a known follow-up; for now, BP10–BP12 (breakdown paragraph repetition) and BP2 (example scenario repetition) provide partial coverage, and AS1–AS3 (which are field-agnostic) catch the salt-token patterns in those fields directly.

## EI. Evidence integrity (testimonials must never masquerade as research)

**The defect class.** Trust is load-bearing. The old books either cite real, verifiable specifics (48 Laws: "Coco Chanel… in 1939 closed every workshop except the perfume operation; in 1954, at seventy-one, she reopened") or present fiction as plainly illustrative (Atomic Habits' fictional nurse is never called a study). The new pipeline regressed: it writes **testimonials dressed as research** — a first-name/initial-only subject whose personal report/account is given the grammar of a finding ("Brad's report names the hinge", "Candace P.'s report gives her the test", "John's Maui habit report makes the rule", "the success report names ketogenic diet adherence"), and in the worst case keys a quiz answer to one. A related semantic variant is the **Piper move**: inserting an invented character into a real researcher's documented setting to act out the finding ("Piper, in Schultz's real lab, voices the discovery").

**The rule.** Every load-bearing claim resolves to either (a) a REAL named source with specifics (a person/company/study/place/date, cited by surname or full name) or (b) a PLAIN illustration carrying no evidentiary verb. A first-name/initial-only account worn as proof is the forbidden third thing. **Hard rule: a quiz answer may never be keyed to a testimonial.**

**Detection (calibrated ZERO-FP on the gold corpus — daring-greatly + start-with-why — and leaving real cited sources like "Kosfeld's case shows" / "Enron's 2001 bankruptcy" untouched).** A noun-class split is the key: a **testimonial noun** (report / account / success report) fires for any given-name owner; a **research noun** (case / study / result / findings) fires ONLY for an unambiguous lone-initial owner ("Candace P.'s study"), which a real source is never written as. Ownership-adjacency (the owner must directly own the noun within ≤2 premodifiers) — not mere sentence co-occurrence — is what avoids the "A trend report shows Veronica's team" / "Jenna's tally … one report" false positives, and real full names ("Michael Kosfeld's result"), companies, and document props are excluded. When a v2 sidecar is present, an owner that matches a real namedExample/hardSpecific entity is exempted. The Piper move is SEMANTIC (a regex can't tell invented "Piper" from real "Schultz") and is handled by the authoring law (STEP-2 R7) + the QC publishable-bar (`factual_accuracy` = CORRUPTION), not the deterministic gate.

## Final gate

A chapter cannot ship to `state/chapters/` unless it passes the **chapter ship gate**, which runs every check above and fails closed on any BLOCKER. ### What "great first-run book" requires going forward

For a writer agent to produce a clean book on the first Step 2 pass:

1. **Source-ground every example.** Open the sidecar before composing each chapter's examples. Each scenario must contain at least one proper noun from the sidecar's `namedExamples`, `centralConcept`, `hardEdge`, or `paraphraseNotes`. SC9 enforces this at chapter-gate time.
2. **Vary `correctIndex` per chapter.** Score each choice for correctness, distribute 0/1/2 with balanced count, ensure the 9-element sequence differs from every prior chapter's. AS12 enforces this at chapter-gate time.
3. **Tier progression in breakdowns.** fastRead, deepRead, fullRead each open with a different first sentence. No paragraph reused across chapters' breakdowns. No 5-token stock phrase shared with ≥2 prior chapters. AS10, AS11, E2 enforce these at chapter-gate time.
4. **Run `gate-chapter` between every chapter.** Mandatory in the Step 2 prompt. Defer the gate until the end and templating compounds undetected across 14 chapters.
5. **Run `book-gate <bookId>` to QC.** Auto-derives brief + plan. Reports all cross-chapter patterns the chapter-time gates can't see.

A book that follows these rules from chapter 1 should pass `book-gate` with 0 blockers on the first Step 2 attempt.
