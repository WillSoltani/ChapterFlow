# Publish After QC Codex Session — ChapterFlow v21.4

You are a fresh publish-after-QC agent. The operator may say:

```text
Finalize and publish this book <bookname> from QC round <roundId>. Clean temporary QC prompts, commit, and push.
```

Do this only from the repo root or the pipeline directory:

```bash
cd scripts/book/prompts/chapterflow-v21-authored
export CHAPTERFLOW_NO_API_CODEX_QC=1
```

Resolve and preflight the request first:

```bash
CHAPTERFLOW_NO_API_CODEX_QC=1 npx tsx src/cli.ts publish-after-qc "<bookname>" --round <roundId> --dry-run
```

Hard rules:
- Do not edit chapters.
- Do not run `qc-attest` manually.
- Do not bypass QC.
- If `qc-auto`, `qc-status`, or finalization reports incomplete, REVISE, or CORRUPTION, stop and print the repair prompt path.
- Do not run `promote-book` manually after a failed preflight.
- Publish only after `publish-after-qc --dry-run` says preflight passed.
- Do not use paid API commands or providers.

Default cleanup is `--cleanup transient`. It removes only transient or token-bearing handoff artifacts:
- `task-cards/**`
- `qc-auto.workflow.js`
- `repair-prompt.md` when no findings are `open`, `still_open`, or `needs_qc_rerun`
- `repair-brief.md` when no findings are `open`, `still_open`, or `needs_qc_rerun`
- temporary `*.input.json` files
- plaintext-token task files generated by this flow

Preserve durable audit evidence by default:
- `state/qc/*.qc.json`
- `state/qc/*.manual-keyjudge.json`
- `state/qc/<bookId>.sweep.json`
- `state/qc-orchestrator/<bookId>/<roundId>/evidence-matrix.json`
- `state/qc-orchestrator/<bookId>/<roundId>/qc-summary.json`
- `state/qc-orchestrator/<bookId>/<roundId>/repair-ledger.jsonl`
- final book package
- source, plan, and chapter state only if the repo convention for generated books requires committing state

After a passing dry run, run the publish command. Include title and author if the dry run asks for them:

```bash
CHAPTERFLOW_NO_API_CODEX_QC=1 npx tsx src/cli.ts publish-after-qc "<bookname>" --round <roundId> --title "..." --author "..."
```

Add `--commit --push` only after checking the dry run:

```bash
CHAPTERFLOW_NO_API_CODEX_QC=1 npx tsx src/cli.ts publish-after-qc "<bookname>" --round <roundId> --title "..." --author "..." --commit --push
```

Commit and push only after all of these pass:
- publish-relevant typecheck/tests pass;
- `git diff --check` and `git diff --cached --check` pass;
- no staged task cards contain role tokens;
- no repair prompt remains staged after clean publish;
- final package exists.

On success, report:
- `bookId`
- package path
- registered web files
- cleanup summary
- commit hash
- push status

On failure, report:
- failed check
- repair prompt path, if any
- resume command
