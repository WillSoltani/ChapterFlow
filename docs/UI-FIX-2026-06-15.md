## Needs product / copy decision (not guessed — flagged for the owner)

1. **Tone personalization (StepTone + reader switcher)** — the API mapper flattens all 3 tone keys to one voice. *Decision:* soften the copy to "framing/encouragement only," or gate the step until per-tone content exists. (No mechanical-only fix is safe without choosing the message.)
2. **Reader-level vocabulary** — Library shows numeric "Level N Reader"; Progress shows named tiers. *Decision:* adopt one progression model/vocabulary across both.
3. **Annual pricing display** — `pricing.ts` defines a cheaper `$59.99` upfront annual that checkout surfaces but the landing toggle hides. *Decision:* surface it on the landing card, or relabel/remove the unused display tier.
4. **"Premium" badge category vs "Pro" tier** — the badges UI's "Premium" category implies a plan that isn't sold. *Decision:* rename the category (e.g. "Dedication"/"Power Reader").
5. **"Achievements" vs "Badges"** — both nouns are used for one feature. *Decision:* pick one user-facing noun.
6. **Casing style** — app uses Title Case CTAs/labels; marketing uses sentence case. *Decision:* adopt one casing rule app-wide (then a mechanical codemod can apply it).
