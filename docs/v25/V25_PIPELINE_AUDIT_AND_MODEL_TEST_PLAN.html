The 30-second version

  • What the pipeline does: an operator types generate-book; a GPT-5.6 Sol model writes whole chapters in a locked sandbox; deterministic code checks structure, quizzes and readability; Sol-family readers trigger small bounded repairs; a separate blind Claude panel (called D7) is the only real quality judge; publish re-checks everything.
  • Is it ready to compare Sol vs Terra vs Luna? No. A readability formula tuned to Sol's writing style kills Terra and Luna chapters before they finish writing, and the D7 judging machinery rejected ~38% of its own rating sessions in the only live run.
  • The owner's one-chapter result (Luna & Terra beat Sol, and cost less): a promising reason to run the experiment — but one chapter per model proves nothing by itself, and the prices are owner-supplied, not verified.
  • Before any whole book: 3 small fixes + a judge calibration drill (Stage 0), then a blinded 18-chapter screening (Stage 1), then a fresh confirmation round (Stage 2). Hard cap: 150 live sessions, fixed rules written down before results exist.

What the first screening run actually did (2026-07-17)

One blinded run: Sol vs Terra vs Luna, one chapter (Nudge ch. 3), all at xhigh effort. Labels A/B/C hid the model names from every reviewer. Result:

0 / 3
models with a valid quality score
2 / 3
models blocked by the readability formula before writing anything (Terra ease 54.2, Luna 47.7 — floor is 70)
5 / 13
judge rating sessions rejected by the validator (~38%) — each a 10–25 min Claude session
10 min
between the saved “Sol INELIGIBLE” verdict (14:32 UTC) and the retry that cured the failure (14:43 UTC)
  • Sol was the only model that produced a chapter. Its blind audit then stalled: a hidden “calibration” rating (a reference chapter the judges re-score to prove they're accurate) came back with self-inconsistent arithmetic and was rejected.
  • The run saved its scoreboard at that moment — “winner: none, Sol ineligible.” Ten minutes later a retried rating passed. The saved verdict was never updated. This audit hand-recomputed the surviving record: its math is exactly right. The saved “arithmetic mismatch” verdict describes a dead attempt, not the surviving evidence.
  • Even the surviving rating scored the reference chapter 74.3 where the owner's benchmark says 67.7 — a 6.6-point miss, over twice the allowed ±3 tolerance. The judge panel has not yet proven it is calibrated.
  • Failed rating attempts are deleted on retry, so 4 of the 5 rejection reasons are unknowable now.
  • Only 1 of the 6 planned screening invocations ever ran.

Bottom line: no evidence about model quality exists yet — for or against any model. The owner's one-chapter comparison remains the only cross-model signal, and it was made outside this machinery.

Failure & repair — every loop is bounded

  • MODEL Write fails a gate → 1 retry, then 1 “simpler lead” retry → chapter marked failed
  • MODEL Review finds defects → targeted repair, cap 2 rounds; regeneration cap 2 per chapter / 3 per book → then quarantine, never silent pass
  • GATE D7 book verdict fails → 1 re-author round → terminal HALT for the owner (no loop)
  • CODE Any promote blocker → QUARANTINE record; no package written
  • GATE D7 rater record invalid (bakeoff) → re-dispatch — currently unbounded and evidence-destroying; fix = attempt cap 3 + keep every attempt (V25-AUD-02)
  • CODE Crash mid-run → lock stolen safely, phase re-derived from disk, finished chapters reused by hash — resume is precise except the stale-verdict bug (V25-AUD-03)

  • 42-package build-out under time pressure (AUD-13)
  • → bakeoff reused production gates with no severity contract → readability censored 2 of 3 models (AUD-01)
  • → only Sol reached the judge, whose task demands model-computed arithmetic → stochastic slips + fail-closed validator + evidence-destroying retries (AUD-02)
  • → one calibration slip voided Sol at the moment the verdict file was written → stale false verdict retained (AUD-03, 07)
  • → no CI could catch any of it (broken/mistargeted for this branch) (AUD-06) and the status docs had already drifted (AUD-11)
  • Net effect: zero valid evidence, misleading artifacts, ~2× judge spend — with every link individually small and fixable.

The experiment — stage by stage

Spend is hard-capped, but the cap itself needs an owner ruling: decision D-3's ratified wording caps 150 codex sessions with the Claude judge sessions tracked separately, while the screening code charges both kinds against one 150 budget (~11 already spent). Until the owner rules, the plan binds itself to the stricter combined reading: planned path ≈ 134 of the 139 remaining; the existing budget guard halts before any breaching session; if money runs short before the confirmation stage, a pre-named replicate is dropped or the campaign halts for re-authorization — never a favorable-case drop, never an overrun, never a screening without its confirmation stage. All rules, bars and caps are fixed before any result exists.

  1. Stage 0a — Instrument qualification (0 live calls). Ship the three fixes (measure-only readability · derive-don't-reject arithmetic with kept attempts & cap 3 · terminal-state verdicts), replay the retained failure records, re-run the model-free suites. Any red stops here.
  2. Stage 0b — Judge drill (≤10 sessions, separately approved). Full blind audits of two owner-benchmarked chapters — one mid-band (~68), one decision-band (~85). Go: ≥5/6 first-attempt-valid records and both audits within ±3 of the benchmark. Miss → stop, fix the instrument, re-drill. No authoring money is spent before the judge is proven.
  3. Stage 1 — Blinded screening (≤36 authoring + ≤90 judge sessions). Sol, Terra, Luna at the same xhigh effort × 3 frozen chapters × 2 independent generations = 18 chapters, all blind-judged. Gate failures are measured, preserved and still scored — they just can't ship. Advance ≤2 models: no safety hard-fail, mean D7 ≥75, no chapter block <60. None qualify → Sol stays provisional; stop. A Sol@high arm runs separately and only informs effort policy.
  4. Stage 2 — Fresh confirmation (≤16 authoring + ≤38 judge sessions). Top two on fresh generations: one held-out chapter from an under-represented genre + the most separating Stage-1 chapter. First-pass and post-repair results reported separately. Confirmed if the leader keeps its direction on ≥3 of 4 cells and the holdout doesn't invert.
  5. Stage 3 — Only if too close to call. More paired chapters, only under a new owner authorization. No automatic max-spend.
  6. Stage 4 — One full-book pilot (outside this task, owner-approved). Requires the pre-pilot fixes (halt-at-ready publish, uniform D7 requirement, receipt-in-package). Acceptance: D7 book verdict PASS (mean ≥85 / min ≥80) within ≤2 repairs. Rollback: quarantine; default reverts to Sol.

How the default gets decided (pre-registered)

  • Unresolved safety/integrity hard failure? → that model is out, whatever its scores.
  • One model >3 D7 points better (consistent across chapters) and cheaper per accepted chapter? → it wins: provisional default + pilot candidate.
  • Top models within ±3 points (statistically indistinguishable)? → cheaper per accepted chapter wins — but only if a dated, owner-approved price table exists; otherwise it's declared a quality tie and the owner decides with cost marked PRICE NOT VERIFIED.
  • Cheaper model >3 points worse? → price cannot rescue it.
  • Quality and cost pull in opposite directions with no dominant option? → present the trade-off; HUMAN owner decides; no invented utility weights after seeing results.
  • Nobody clears the bar? → Sol stays provisional, campaign stops, the bar does not move.
  • The owner's blind preference is recorded before unblinding and may only break a declared tie or sign off the pilot — never override mid-test. The original n=1 comparison carries zero evidentiary weight.

Glossary

D7
The blind quality audit: two independent Claude raters score a chapter on 8 learning-quality domains (0–4 each), an adjudicator settles differences, code recomputes all arithmetic, and the result is sealed into a receipt. The pipeline's only semantic ship gate.
Deterministic floor
The pure-code checks every chapter must pass — structure, quiz hygiene, seams, lengths. No model involved; same input always gives the same answer.
Calibration (unit / anchor)
A reference chapter the owner has already scored. Judges secretly re-score it each run; if they land more than ±3 points from the benchmark, the whole audit is voided — proof the judges drifted, not the book.
CAS / atomic write
“Compare-and-swap” style file writes: a chapter is written to a temp file and renamed into place, so a crash can never leave a half-written chapter.
Receipt
A sealed, hash-bound record proving a specific chapter's bytes passed the D7 audit. Tampering, staleness, or a different chapter voids it.
Bakeoff
A blinded side-by-side trial: several models write the same chapter from identical frozen inputs; judges score them without knowing which model wrote which.
