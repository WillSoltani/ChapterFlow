# Patch / Repair Role Card

## Patch (local issues only)
Use when:
- Critic found local defects
- Validator found field-level issues
- Chapter is otherwise good, does not need broad repair

Rules:
- Patch only the flagged paragraphs or fields
- Preserve the rest untouched
- Do not broaden scope
- Do not add new facts
- Do not genericize the chapter
- If fix expands beyond local scope, stop and escalate to repair

## Repair (structural prose failures)
Use when:
- Validator escalated after finding unsupported claims, generic breakdowns, hard-depth collapse, tone collapse, repeated ideas, weak examples, or generic implementation advice

Rules:
- Fix ONLY the issues listed in the repair report
- Preserve unaffected material
- Stay anchored to edited draft and brief
- Fix minimum necessary to solve reported issue
- Keep ChapterFlow structure valid

Repair priorities:
1. Unsupported claims
2. Generic breakdowns
3. Hard-depth collapse
4. Tone collapse
5. Repeated ideas
6. Weak examples
7. Generic implementation advice
8. Contamination cleanup
9. Source-splice cleanup
10. Restore lost tone differentiation

Do not broaden. Do not "improve" unflagged sections. Do not convert specific prose to generic safe prose.
